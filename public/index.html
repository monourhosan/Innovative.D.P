💡 How this Companion App Works
  1. Step 1: The Android app authenticates with /api/v1/auth/login using the Team Member's User ID and Password.
  2. Step 2: The app fetches the projects assigned to their Supervisor via /api/v1/member/projects.
  3. Step 3: The dynamic form fields (text, number, choices, GPS, dates) are rendered based on the project's form_schema_json.
  4. Step 4: Submissions are sent to /api/v1/member/submissions (with offline batch queue support).
  5. Step 5: The central backend saves the record, attaches metadata (Supervisor ID, Team Member ID, timestamp), and triggers an SSE broadcast to the Admin Live Dashboard!

⚡ REST API Contract for Companion Android Apps
Base URL: /api/v1

Complete endpoint reference for the companion Android applications. All requests accept and return JSON. CORS is fully enabled.

POST /api/v1/auth/login
Role: All (Admin, Supervisor, Member)
Authenticates user_id & password. Returns JWT token, user profile, and supervisor relationship. 
// Request Body
{
  "user_id": "SUP-1042",
  "password": "supervisor123"
}
GET /api/v1/supervisor/dashboard
Role: SUPERVISOR
Returns live supervisor stats: team members count, total submissions, today submissions, and per-member breakdown. 
Click "Run Test Call" to execute live against backend
GET /api/v1/member/projects
Role: TEAM_MEMBER
Returns active projects with full form_schema JSON for dynamic rendering on the Android app. 
Click "Run Test Call" to execute live against backend
POST /api/v1/member/submissions
Role: TEAM_MEMBER
Submits single collected form data or batch array of submissions for offline sync. 
// Request Body (Single or Batch Array)
{
  "project_id": 1,
  "answers_json": {
    "respondent_name": "Jannatul Ferdous",
    "respondent_age": 32,
    "gender": "female",
    "primary_water_source": "tube_well"
  },
  "client_timestamp": "2026-10-14T20:30:00Z"
}
GET /api/v1/member/dashboard
Role: TEAM_MEMBER
Returns the Team Member's personal stats (today's count, total count, recent submissions list).
